# 차량 반납·추가 (리스 반납 / 렌트 신규) 설계

작성일: 2026-11-23

## 의도

법인차량 리스를 반납하면 그 차량의 기존 탭을 비활성화하고, 새로 렌트하면 차량 탭을 새로 추가한다.
차량번호 자체가 바뀌는 교체다. 같은 차량을 기간별로 끊는 것과는 다르다.
처리는 개발자 본인이 GAS 에디터에서 한다.

## 목표

- 반납한 차량은 더 이상 기록을 받지 않는다. 차 안에 남은 QR(`?car=`)과 주차 보드 링크로 들어와도 막는다.
- 반납한 차량의 운행기록부(차량 탭)와 RAW 이력은 그대로 남긴다. 세무 증빙이다.
- 새 차량은 `차량_마스터`에 행 하나를 추가하고 함수 하나를 실행하는 것으로 탭 생성과 등록이 끝난다.

## 비목표

- 스프레드시트 커스텀 메뉴 등 비개발자용 UI
- `fixedUser`·`businessTripCars`를 `config.html`에서 `차량_마스터`로 옮기는 일. 새 차량이 둘 중 하나라면 지금처럼
  `config.html` 수정 → 배포 → `setupProperties`로 처리한다.
- QR 생성
- `차량_마스터`에 없는 차량번호 차단. 지금은 미등록 차량도 폼이 열리며, 이 동작은 유지한다.

## 반목표 (이렇게 되면 실패)

- RAW 수정·삭제
- 반납 차량 탭의 데이터 손실(삭제, 이름 변경으로 `syncAllCarSheets` 대상에서 빠짐)
- 새 차량 탭에 이전 차량의 15행 이하 데이터가 남아 `getPrevOdoData`가 엉뚱한 직전 계기판을 읽는 것

## 제약

- RAW는 SSOT. 이 기능은 RAW를 건드리지 않는다.
- 차량 탭은 시트명 = 차량번호(`ss.getSheetByName(carNo)`)로 찾는다. 반납 탭도 이름을 바꾸지 않는다.
- `CONFIG.DATA_START_ROW = 15`, `CAR_TOTAL_COLS = 44`
- 배포는 `staging` → test 검증 → `main` 순서. `syncCarRegistry`는 트리거 없이 필요할 때 수동 실행하며, test와 prod 각각에서 한다.

## 접근 방법

| 안 | 내용 | 트레이드오프 |
|---|---|---|
| **A (채택)** | `차량_마스터`에 `반납일` 열을 둔다. 인자 없는 idempotent 함수 `syncCarRegistry`가 시트 상태에 맞춰 탭 숨김·생성과 `CAR_META_JSON` 갱신을 처리한다 | GAS 에디터에서 바로 실행할 수 있고, 반납 이력이 시트에 남는다 |
| B | 명령형 `retireCar(carNo)` / `addCar(carNo, 차종)` | GAS 에디터는 인자를 못 넘기므로 매번 코드를 고치거나 wrapper가 필요하다. 상태 저장용 마스터 열도 결국 필요하다 |
| C | 입력 차단만 코드로 하고 탭 관리는 수동 | 코드가 가장 적다. 그러나 수동 복제 때 15행 이하를 안 지우면 새 차량의 직전 계기판이 오염된다 |

사용자가 A를 골랐다. 지금 쓰는 "`차량_마스터` 수정 → `setupProperties` 실행" 흐름과 같고, 반납·추가가 함수 하나로 끝난다.

## 설계

### 데이터

- `차량_마스터` **F열 = `반납일`** (날짜). 비어 있으면 운행 중인 차량이다. A~E열의 의미는 그대로다.
  F1 헤더가 비어 있으면 `syncCarRegistry`가 `반납일`을 써 넣는다.
- `CAR_META_JSON`의 차량별 객체에 `반납일`을 추가한다. 값은 `normalizeReturnDate`로 정규화한다.
  Date 셀은 KST `yyyy-MM-dd`로, 그 외 값은 trim한 문자열로 바꾼다.
- `setupProperties`에서 carMeta를 만드는 부분을 `_buildCarMeta(rows)`로 분리해 `syncCarRegistry`와 같이 쓴다.
  차량번호는 trim한다.

### 반납 판정 — 순수 함수 `isRetiredCar(반납일, todayStr)`

staging 워크트리에 커밋되지 않은 채 남아 있던 구현(2026-11-20)을 이어받는다. 판정 규칙만 바꾼다.

- 반납일이 `yyyy-MM-dd`이면 **반납일 < 오늘(KST)**일 때 반납으로 본다.
  반납일 당일은 반납하러 가는 운행도 기록해야 하므로 입력을 허용한다. 미래 날짜를 미리 적어 두어도 된다.
- 비어 있지 않은데 날짜 형식이 아닌 값(예: `반납`)은 즉시 반납으로 본다. 기존 구현의 규칙을 유지한다.
  `syncCarRegistry`는 이런 값을 경고 로그로 남긴다.
- 마스터에 없거나 반납일이 비어 있으면 반납이 아니다.
- Node 하네스로 단위테스트한다.

### 판정 적용 지점

| 지점 | 동작 |
|---|---|
| `serveForm` | 반납 차량이면 폼 대신 "반납된 차량입니다 (반납일 yyyy-MM-dd)" 안내 페이지를 반환한다 |
| `saveRecord` / `updateRecord` | lock 획득 후 판정하고, 반납이면 throw한다. 반납 판정 전에 폼을 열어 둔 경우를 막는다 |
| `_buildParkingBoard` | 반납 차량은 결과에서 뺀다 |

`syncAllCarSheets`와 `exportToExcel`은 변경하지 않는다. 반납 차량 탭도 매일 재정렬로 RAW와 일치하게 유지되고, 월간 백업에 들어간다.

### `syncCarRegistry()` — 수동 실행, idempotent

`차량_마스터`의 각 행에 대해:

1. **반납일 있음**: 차량 탭을 `hideSheet()`한다. 숨김은 화면에만 영향을 주며, 판정은 위의 날짜 규칙을 따른다.
2. **반납일 없음, 탭 있음**: 숨겨져 있으면 `showSheet()`한다(반납 취소).
3. **반납일 없음, 탭 없음**: 기존 차량 탭을 복제해 이름을 차량번호로 바꾸고, 15행 이하를 `clearContent`한다.

그다음 `CAR_META_JSON`을 갱신하고 `parking_board` 캐시를 지운 뒤, 생성·숨김·복원한 차량 목록을 `Logger.log`로 남긴다.

### 새 탭의 복제 원본

- 마스터 순서상 처음 나오는, 탭이 있는 **반납 안 된** 차량의 탭을 쓴다. 없으면 탭이 있는 반납 차량의 탭을 쓴다.
- 원본 후보가 하나도 없는데 만들 탭이 있으면, 아무것도 바꾸기 전에 생성 대상 차량번호를 담아 throw한다.
- 머리말(1~14행)에는 원본 차량의 정보가 남는다. 코드는 머리말을 읽지 않으므로 앱 동작에는 영향이 없고,
  실행 로그에 "머리말을 고치세요" 안내를 원본 차량번호와 함께 남긴다.
- (2026-11-23 변경) 처음에는 전용 `차량_양식` 시트를 원본으로 썼다. 머리말은 어차피 손으로 채우므로 양식이 주는 효과가
  "빈 머리말" 하나뿐인 데 비해, test·prod 각각 1회 준비가 필요하고 양식이 없으면 sync가 막혀 사용자 결정으로 제거했다.

### 운영 절차

- **반납**: `차량_마스터` F열에 반납일 입력 → `syncCarRegistry` 실행
- **추가**: `차량_마스터`에 행 추가(A 차량번호, B 차종, D 법인명, E 사업자번호) → `syncCarRegistry` 실행 →
  새 탭 머리말의 차량 정보 기입 → 폼에서 "초기값 등록". 전담·출장 차량이면 `config.html` 수정 → 배포 → `setupProperties`도 한다.
- `CLAUDE.md`의 운영 함수 항목에 `syncCarRegistry`를 추가한다.

## 확정한 것

- 반납일 **당일까지 입력 허용**, 다음 날부터 차단 (2026-11-23 사용자 확정)
- 새 탭 원본은 기존 차량 탭 복제(반납 안 된 탭 우선). 전용 `차량_양식` 시트는 쓰지 않는다 (2026-11-23 사용자 확정)
- 반납 탭은 삭제·이름 변경 없이 **숨김만** 한다
- 반납 판정 시 폼은 열지 않고 안내 페이지만 보여준다. 페이지는 `HtmlService.createHtmlOutput`으로 짧게 만든다.
- 작업 위치는 `pen-paper-away-project-staging` 워크트리(`staging` 브랜치)이며, 남아 있던 미커밋 변경 위에서 이어간다.
  단위테스트 하네스(`test/harness.js`, `package.json`)는 `sample` 작업 트리에서 가져온다.
