# 주차 보드 ↔ 차량_마스터 연동 설계 (짧은 설계)

## 의도

- **신규 차량을 처음 쓸 때**: QR을 붙이기 전이라도 주차 보드 카드의 "운행일지 기록하기"로 폼에 들어가 초기값 등록을 할 수 있어야 한다.
- **기존 차량을 보드에서 뺄 때**: 운영자가 마스터에서 직접 정한다. 반납일을 기다리지 않아도 된다.

지금은 보드의 차량 목록이 RAW에서 나온다(`Code.js` `_buildParkingBoard`). 그래서 마스터에 막 추가한 차량은 첫 실제 운행 전까지
보드에 없고, 마스터에 없는 차량번호라도 RAW에 기록이 있으면 보드에 나온다.

## 접근

| 안 | 내용 | 결론 |
|---|---|---|
| **A** | 보드 목록을 마스터 기준으로 하고, 마스터 G열 `위치기록여부`가 TRUE인 차량만 띄운다 | **채택** (사용자 제안) |
| B | RAW 기준을 유지하고 초기값등록 행만 포함 | 초기값 등록 전에는 여전히 보드에 없어 신규 차량의 첫 진입을 못 푼다 |
| C | 폼에 차량 선택 드롭다운 | 화면이 늘고 QR(`?car=`) 흐름과 겹친다 |

`위치기록여부 = FALSE`의 의미는 **보드 표시만 끈다**(사용자 선택 (a)). 폼은 지금처럼 주차위치가 필수이고 RAW에도 기록한다.
그래서 다시 켜면 최신 위치가 바로 보인다. (b) "폼에서도 주차위치 생략"은 채택하지 않았다.

## 설계

### 마스터 G열 `위치기록여부`

- 체크박스. 보드에는 **G = TRUE이면서 반납 아닌 차량**만 띄운다(반납 조건 AND는 내 판단 — 반납 후 체크 해제를 잊어도 빠지도록).
- `CAR_META_JSON`의 차량별 `위치기록: boolean`으로 담는다. `setupProperties`·`syncCarRegistry` 둘 다 같은 읽기 함수(`_readCarMaster`)를 쓴다.
- 값 해석: `true` 또는 문자열 `"TRUE"`(대소문자·공백 무시)만 TRUE, 나머지(빈 칸 포함)는 FALSE.
- **G1 헤더 규칙** (F1과 같은 방식):
  - `위치기록여부` → 행별 값을 따른다.
  - 비어 있음 → 아직 도입 전으로 보고 **모든 차량 TRUE**. 배포 직후 `setupProperties`가 먼저 돌아도 보드가 비지 않게.
  - 그 밖의 값 → 두 함수 모두 아무것도 바꾸기 전에 throw.
- **첫 sync 마이그레이션**: G1이 비어 있으면 `syncCarRegistry`가 G1에 `위치기록여부`를 쓰고, 차량 행마다 체크박스를 넣는다
  (반납 아닌 차량은 체크, 반납 차량은 해제). 이후로는 시트 값을 따른다.
- 예전에 만든 `CAR_META_JSON`에 `위치기록` 키가 없으면 TRUE로 본다(`!== false`). 배포 후 sync 전까지 보드가 비지 않게.

### 보드 목록 (`_buildParkingBoard`)

1. `CAR_META_JSON`의 차량을 **마스터 행 순서**로 돈다. `위치기록 !== false`이면서 반납 아닌 차량만 남긴다.
2. 각 차량에 RAW 최신 기록을 붙인다. **초기값등록 행도 포함**해 주차위치를 보여 준다. 운전자는 비어 있으므로 카드에 `—`로 나온다.
3. RAW 기록이 없으면 `parking: ""`, `name: ""`, `time: "—"` 카드를 만든다. 지금 UI는 이를 `미기록 / — / —`로 그린다.
4. 마스터에 없는 차량번호는 RAW에 기록이 있어도 나오지 않는다.

### sync 경고

- RAW에 있는데 마스터에 없는 차량번호를 `syncCarRegistry` 실행 로그에 `경고:`로 남긴다. 반환값 `warnings`에도 넣는다.
  prod 마스터에 빠진 차량이 있으면 배포 후 보드에서 사라지므로 미리 확인하는 용도다.

### 운영 절차 (CLAUDE.md 갱신)

- **신규**: 마스터에 행 추가 + G 체크 → `syncCarRegistry` → 보드에 `미기록` 카드 → 카드에서 초기값 등록 → 위치 표시.
- **보드에서만 빼기**: G 체크 해제 → `syncCarRegistry`. 보드 캐시가 지워져 바로 반영된다.
- **반납**: 지금과 같다(F열 반납일 → sync → 다음 날부터 보드·폼에서 빠짐).

## 비목표

- 폼의 `?car=` 값을 마스터와 대조하는 검증
- 폼에서 보드로 가는 링크
- 위치기록 FALSE 차량의 폼에서 주차위치 생략 ((b)안)

## 제약

- `CAR_META_JSON`은 script property 하나다(값당 9KB 한도). 차량당 `"위치기록":true` 약 20바이트가 늘어난다.
- 마스터를 고친 뒤 반영은 지금처럼 `syncCarRegistry` 실행 시점이다. 보드는 시트가 아니라 `CAR_META_JSON`을 읽는다.
